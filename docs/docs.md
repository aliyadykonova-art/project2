# Документация проекта

## Модуль `masks`

Модуль содержит функции для маскировки номеров банковских карт и счетов.

### `get_mask_card_number`

```python
get_mask_card_number(card_number: str) -> str
```

Маскирует номер банковской карты. Сохраняет первые шесть и последние четыре символа, а символы между ними заменяет звёздочками. Номер форматируется с пробелами между блоками по четыре символа.

**Параметры:**
- `card_number` — номер банковской карты в виде строки.

**Возвращает:**
- `str` — замаскированный номер карты.

**Пример:**

```python
get_mask_card_number("1234567890123456")
```

Результат:

```text
1234 56** **** 3456
```

### `get_mask_account`

```python
get_mask_account(card_number: str) -> str
```

Маскирует номер банковского счёта: оставляет последние четыре символа и добавляет перед ними две звёздочки.

**Параметры:**
- `card_number` — номер банковского счёта в виде строки.

**Возвращает:**
- `str` — замаскированный номер счёта.

**Пример:**

```python
get_mask_account("1234567890123456")
```

Результат:

```text
**3456
```

## Модуль `widget`

Модуль содержит функции для форматирования данных банковских карт и счетов, а также преобразования дат.

### `mask_account_card`

```python
mask_account_card(info: str) -> str
```

Определяет тип банковского продукта по названию и маскирует его номер. Если название начинается со слова «Счет» (без учёта регистра), используется маскировка счёта. В остальных случаях применяется маскировка банковской карты.

**Параметры:**
- `info` — строка с названием карты или счёта и номером.

**Возвращает:**
- `str` — название продукта с замаскированным номером.

**Пример:**

```python
mask_account_card("Visa Platinum 1234567890123456")
```

Результат:

```text
Visa Platinum 1234 56** **** 3456
```

Пример для счёта:

```python
mask_account_card("Счет 1234567890123456")
```

Результат:

```text
Счет **3456
```

### `get_date`

```python
get_date(date_string: str) -> str
```

Извлекает дату из строки до символа `T` и преобразует её из формата `YYYY-MM-DD` в формат `ДД.ММ.ГГГГ`.

**Параметры:**
- `date_string` — строка с датой, например в формате ISO с датой и временем.

**Возвращает:**
- `str` — дата в формате `ДД.ММ.ГГГГ`.

**Пример:**

```python
get_date("2024-03-11T02:26:18.671407")
```

Результат:

```text
11.03.2024
```

## Модуль `processing`

Модуль предназначен для обработки списков банковских операций: фильтрации по статусу и сортировки по дате.

### `filter_by_state`

```python
filter_by_state(
    data_list: list[dict],
    state: str = "EXECUTED"
) -> list[dict]
```

Фильтрует список словарей по значению поля `state`. В результат попадают элементы, у которых значение этого поля совпадает с параметром `state`.

**Параметры:**
- `data_list` — список словарей с данными об операциях.
- `state` — статус для фильтрации. По умолчанию `EXECUTED`.

**Возвращает:**
- `list[dict]` — новый список элементов с указанным статусом. Исходный список не изменяется.

**Пример:**

```python
operations = [
    {"id": 1, "state": "EXECUTED"},
    {"id": 2, "state": "CANCELED"},
]

filter_by_state(operations)
```

Результат:

```python
[{"id": 1, "state": "EXECUTED"}]
```

### `sort_by_date`

```python
sort_by_date(
    data_list: list[dict],
    descending: bool = True
) -> list[dict]
```

Сортирует список словарей по значению поля `date`. Исходный список не изменяется.

**Параметры:**
- `data_list` — список словарей, каждый из которых должен содержать ключ `date`.
- `descending` — направление сортировки: `True` — по убыванию (по умолчанию), `False` — по возрастанию.

**Возвращает:**
- `list[dict]` — новый отсортированный список.

**Пример:**

```python
operations = [
    {"id": 1, "date": "2023-01-15"},
    {"id": 2, "date": "2024-03-10"},
]

sort_by_date(operations)
```

Результат: сначала операция от `2024-03-10`, затем операция от `2023-01-15`.

## Модуль `generators`

Модуль содержит генераторы для последовательной обработки банковских транзакций.

### `filter_by_currency`

```python
filter_by_currency(
    transactions: list[dict],
    currency_code: str = "USD"
) -> Iterator[dict]
```

Последовательно перебирает транзакции и выдаёт только те, у которых код валюты в `operationAmount.currency.code` совпадает с параметром `currency_code`.

**Параметры:**
- `transactions` — список словарей с транзакциями.
- `currency_code` — код валюты для фильтрации. По умолчанию `USD`.

**Возвращает:**
- `Iterator[dict]` — итератор подходящих транзакций.

### `transaction_descriptions`

```python
transaction_descriptions(
    transactions: list[dict]
) -> Iterator[str]
```

Последовательно выдаёт значение поля `description` каждой транзакции. Если поле отсутствует, выдаётся пустая строка.

**Параметры:**
- `transactions` — список словарей с транзакциями.

**Возвращает:**
- `Iterator[str]` — итератор описаний операций.

### `card_number_generator`

```python
card_number_generator(start: int, stop: int) -> Iterator[str]
```

Генерирует номера в диапазоне от `start` до `stop` включительно. Каждый номер форматируется как 16 цифр с ведущими нулями и разделяется на четыре блока по четыре цифры.

**Параметры:**
- `start` — начало диапазона.
- `stop` — конец диапазона включительно.

**Возвращает:**
- `Iterator[str]` — генератор форматированных номеров.

**Пример:**

```python
for number in card_number_generator(1, 3):
    print(number)
```

Результат:

```text
0000 0000 0000 0001
0000 0000 0000 0002
0000 0000 0000 0003
```

Примечание: для аннотаций используется `Iterator` из модуля `typing`.

## Модуль `decorators`

Модуль содержит декоратор для логирования выполнения функций.

### `log`

```python
log(filename=None)
```

Декоратор логирует выполнение декорируемой функции. Логирование включает входящие аргументы, результат успешного выполнения и сведения об исключениях.

**Параметры:**
- `filename` — имя файла для записи логов. Если значение `None`, сообщения выводятся в консоль.

**Возвращает:**
- Декоратор, оборачивающий функцию и добавляющий логирование.

**Пример:**

```python
@log()
def add(a, b):
    return a + b
```

Для записи логов в файл:

```python
@log("operations.log")
def add(a, b):
    return a + b
```

Точный формат сообщений и поведение при возникновении исключений зависят от реализации декоратора.

## Модуль `utils`

Модуль предоставляет функции для чтения финансовых данных из JSON, CSV и Excel (`.xlsx`). Для чтения табличных файлов используется библиотека `pandas`. Модуль также настраивает логирование в файл `logs/utils.log`.

### `get_financial_data`

```python
get_financial_data(path: str) -> list[dict]
```

Читает финансовые данные из JSON-файла. Если файл существует и его корневое значение является списком, возвращает этот список.

При отсутствии файла, некорректном JSON, неподходящей структуре данных или другой ошибке функция возвращает пустой список. Информация о чтении и ошибках записывается в лог.

**Параметры:**
- `path` — путь к JSON-файлу.

**Возвращает:**
- `list[dict]` — загруженные данные, если корневое значение JSON является списком.
- `[]` — при ошибке или неподходящей структуре данных.

**Пример:**

```python
from src.utils import get_financial_data

transactions = get_financial_data("data/operations.json")
```

### `read_transactions_from_csv`

```python
read_transactions_from_csv(file_path: str) -> list[dict]
```

Читает CSV-файл с помощью `pandas.read_csv()` и преобразует строки таблицы в список словарей посредством `to_dict(orient="records")`.

При отсутствии файла или ошибке чтения возвращает пустой список.

**Параметры:**
- `file_path` — путь к CSV-файлу.

**Возвращает:**
- `list[dict]` — строки таблицы в виде словарей.
- `[]` — если файл отсутствует или не удалось прочитать данные.

**Пример:**

```python
from src.utils import read_transactions_from_csv

transactions = read_transactions_from_csv("data/transactions.csv")
```

### `read_transactions_from_excel`

```python
read_transactions_from_excel(file_path: str) -> list[dict]
```

Читает Excel-файл с помощью `pandas.read_excel()` и преобразует строки таблицы в список словарей. Для чтения файлов `.xlsx` обычно требуется установленная библиотека `openpyxl`.

При отсутствии файла или ошибке чтения возвращает пустой список.

**Параметры:**
- `file_path` — путь к Excel-файлу.

**Возвращает:**
- `list[dict]` — строки таблицы в виде словарей.
- `[]` — если файл отсутствует или не удалось прочитать данные.

**Пример:**

```python
from src.utils import read_transactions_from_excel

transactions = read_transactions_from_excel("data/transactions.xlsx")
```

### Логирование модуля

При импорте модуля создаётся каталог `logs`, если его ещё нет. Логгер `utils` настроен на уровень `DEBUG`, а файловый обработчик записывает сообщения в `logs/utils.log` в кодировке UTF-8.

Логируются попытки чтения, успешная загрузка и количество записей, отсутствие файлов, некорректная структура JSON и ошибки чтения.

Файловый обработчик создаётся с режимом `w`, поэтому при создании обработчика содержимое файла журнала перезаписывается.

## Модуль `external`

Модуль предназначен для конвертации сумм транзакций в российские рубли через внешний API Apilayer. Для HTTP-запросов используется `requests`, для загрузки переменных окружения из файла `.env` — `python-dotenv`.

### `convert_to_rub`

```python
convert_to_rub(transaction: dict) -> float
```

Извлекает сумму и код валюты из полей `operationAmount.amount` и `operationAmount.currency.code`, затем определяет способ обработки суммы.

Поведение функции:
- Для `RUB` возвращает сумму без конвертации.
- Для `USD` и `EUR` отправляет запрос к API Apilayer для конвертации в `RUB`.
- Если данные транзакции отсутствуют или имеют неподходящий тип, возвращает `0.0`.
- Если для иностранной валюты не задан `API_KEY`, возвращает `0.0`.
- Если сетевой запрос вызывает `requests.RequestException`, возвращает `0.0`.
- При HTTP-статусе `200` возвращает значение `result` из JSON-ответа, преобразованное в `float`.
- Для других кодов валют возвращает исходную сумму.

**Параметры:**
- `transaction` — словарь транзакции с вложенными полями `operationAmount.amount` и `operationAmount.currency.code`.

**Возвращает:**
- `float` — сумма в рублях для RUB и успешно сконвертированных USD/EUR.
- `0.0` — в описанных случаях ошибки.
- Исходную сумму для других кодов валют и для ответа API со статусом, отличным от `200`.

**Пример для RUB:**

```python
from src.external import convert_to_rub

transaction = {
    "operationAmount": {
        "amount": "100",
        "currency": {
            "code": "RUB"
        }
    }
}

result = convert_to_rub(transaction)
print(result)
```

Результат:

```text
100.0
```

**Пример для USD:**

```python
transaction = {
    "operationAmount": {
        "amount": "10",
        "currency": {
            "code": "USD"
        }
    }
}

result = convert_to_rub(transaction)
print(result)
```

Для USD функция отправляет запрос к внешнему API, поэтому результат зависит от текущего курса валют, доступности сервиса и корректности API-ключа.

### Настройка API-ключа

При импорте модуля вызывается `load_dotenv()`, загружающий переменные из файла `.env`, если он доступен. Для конвертации USD и EUR требуется переменная окружения `API_KEY`.

Пример файла `.env`:

```dotenv
API_KEY=your_api_key
```

Не добавляйте реальный API-ключ в исходный код или публичный репозиторий.

### Особенности обработки ошибок

Функция перехватывает `KeyError`, `ValueError` и `TypeError` при чтении данных транзакции, а также `requests.RequestException` при запросе к API.

В текущей реализации HTTP-ответ со статусом, отличным от `200`, приводит к возврату исходной суммы. Для USD и EUR это может быть не сумма в рублях, поэтому такое поведение следует учитывать при дальнейшем использовании функции.

## Тестирование и контроль качества

В проекте используются инструменты автоматического тестирования и статического анализа кода.

### `pytest`

Запускает автоматические тесты:

```bash
pytest
```

### `unittest.mock`

Позволяет заменять внешние зависимости в тестах, в том числе сетевые запросы и переменные окружения. Это помогает проверять поведение кода без обращения к реальному API.

### `mypy`

Проверяет аннотации типов и выявляет ряд ошибок статической типизации:

```bash
mypy .
```

### `flake8`

Проверяет код на соответствие настроенным правилам стиля и выявляет потенциальные проблемы:

```bash
flake8
```

Для воспроизводимой проверки рекомендуется запускать инструменты в виртуальном окружении с установленными зависимостями проекта.
